**Context（上下文 / 語境）** in AI
==========================

在 AI（尤其是大型語言模型如 ChatGPT 或 Ollama）的領域中，**Context（上下文 / 語境）** 指的是 **AI 在處理當前請求時，所能「看見」並「記住」的所有資訊總和。**

你可以把它想像成 AI 的**「短期記憶」**或**「工作桌面」**。

---

### 1. Context 包含什麼？

當你跟 AI 對話時，Context 通常由以下三部分組成：

* **對話歷史**：你剛才問了什麼，以及 AI 剛才回答了什麼。
* **系統提示詞 (System Prompt)**：你設定給 AI 的規則（例如：「你現在是一個專業的律師」）。
* **外部資料**：如果你上傳了一個 PDF 或貼了一段程式碼，這些資料也會被塞進 Context 裡。

---

### 2. 為什麼 Context 很重要？

如果沒有 Context，AI 就會像魚一樣只有秒級記憶。

* **沒有 Context 的對話：**
* 你：「我想去日本旅遊。」
* AI：「日本有很多好玩的地方，例如東京。」
* 你：「那裡天氣如何？」
* AI：「請問你指的是哪裡的天氣？」（因為它忘了上一句在聊日本）


* **有 Context 的對話：**
* AI 會記得「那裡」指的是「日本」，並根據之前的對話回答你。



---

### 3. Context Window（上下文視窗）是什麼？

這是大家最常討論的技術指標，指的是 **AI 記憶力的上限**。

每個模型能處理的 Context 長度是有限的（通常以 **Token** 為單位）。

* 如果對話太長，超過了「視窗」的大小，AI 就會開始**「忘記」**最前面的對話內容。
* 這就像一個滑動的視窗：當新的資訊進來，最舊的資訊就會從另一端掉出去。

---

### 4. 專業術語：Token 與 Context

在 AI 裡，Context 不是按「字數」算，而是按 **Token** 算。

* 1,000 個 Token 大約等於 750 個英文單字或 500-600 個中文字。
* **Llama 3 / 4** 的 Context 通常是 **8K 到 128K**。
* **Gemini 1.5 Pro** 甚至可以達到 **1M - 2M (兩百萬)** Token，這意味著你可以把幾十本書同時塞進它的「短期記憶」裡，它都不會忘。

---

### 5. 為什麼大模型會變笨？（Context 壓力）

當 Context 塞得很滿時，AI 有時會出現「迷失在中間 (Lost in the Middle)」的現象。雖然它理論上「記得」所有資訊，但它可能難以從正中間的段落中提取出精確的答案，而比較傾向於記得開頭和結尾。

---

### 總結

**Context 就是 AI 的「當下記憶」**。Context 越大，AI 就能處理越長的文檔、理解越複雜的對話脈絡。


## **Context Window（上下文視窗）的上限**，是指一個 AI 模型在單次處理中，**「腦袋裡能同時裝下的資訊量極限」**。

如果把 AI 比喻成一個正在讀書的人，Context Window 就是他的**「工作記憶區」**或**「書桌的大小」**。當書桌擺滿了（達到上限），為了放進新的書頁，他必須把最舊的書頁丟掉。

以下是關於這個上限的幾個核心概念：

---

### 1. 達到上限會發生什麼事？

當你的對話長度超過模型設定的上限（例如 8,192 Tokens）時，AI 會出現以下狀況：

* **「斷片」失憶**：它會忘記對話最開頭的設定。例如你一開始叫它「稱呼我為船長」，聊到後來它會突然改口叫你「先生」。
* **邏輯崩壞**：它可能無法理解代碼後面的報錯，因為定義代碼的前半段已經從它的記憶視窗中「滑」出去了。
* **胡言亂語（幻覺）**：當記憶變得破碎，AI 容易產生錯誤的關聯。

---

### 2. 不同模型的上限對比 (2026 年現況)

模型的上限是由開發者在訓練時就定義好的硬體規格。

| 模型類別 | 常見上限 (Tokens) | 體感容量 |
| --- | --- | --- |
| **早期模型 (GPT-3.5)** | 4,096 | 約 5-10 頁 A4 紙 |
| **主流開源 (Llama 3.1/4)** | 128,000 (128K) | 約 1 份厚厚的研究報告或中型合約 |
| **超長 Context (Gemini 1.5/2)** | 1,000,000 - 2,000,000 | 幾十本書，或數小時的影片內容 |
| **Ollama 預設 (num_ctx)** | **2,048 或 4,096** | **通常很小，適合日常簡單對話** |

---

### 3. 硬體對上限的物理限制

為什麼不把所有模型的上限都設成一百萬？因為 **Context 越大，越吃顯示卡的記憶體（VRAM）**。

* **平方增長效能消耗**：在標準架構下，當 Context 長度增加 2 倍，運算量和記憶體消耗通常會呈指數級上升。
* **本地限制**：如果你在 Ollama 跑一個 128K 上限的模型，但你的顯卡只有 8GB VRAM，你可能連 16K 的 Context 都開不起來，因為顯存會直接溢出（OOM, Out of Memory）。

---

### 4. 如何在 Ollama 中檢查或調整上限？

這是最重要的部分。很多時候模型支援 128K，但 **Ollama 預設只會開 2048 或 4096**。

你可以透過參數 `num_ctx` 來手動調大它：

1. 進入執行模式：`ollama run llama3.1`
2. 在對話中輸入：`/set parameter num_ctx 32768` (這會把上限調成 32K)
3. 或者在你的 **Modelfile** 裡寫入：
```dockerfile
PARAMETER num_ctx 32768

```



---

### 5. 總結：上限代表的是「深度理解能力」

一個模型的 Context Window 上限越高，代表它越能：

* **分析長文**：一口氣讀完長篇法律文件。
* **代碼開發**：記住整個專案的多個檔案內容。
* **複雜對話**：維持長達數天的連續對話而不失神。

## 對於 Mac Mini M4 (16GB RAM) 的使用者來說，你擁有一顆非常強大的處理器，但 **16GB 的統一記憶體 (Unified Memory)** 是你玩本地 AI 的主要限制。在 Coding 場景下，這意味著你必須在「模型智商」與「記憶體容量（Context）」之間取得平衡。

以下是針對你的配備，2026 年最推薦的 Coding 模型與參數設定建議：

### 1. 最好用的模型推薦 (Top 3)

對於 16GB RAM 的 Mac，最推薦的是 **7B 到 14B** 之間的模型。

* **第一名：Qwen 2.5 Coder 7B (或最新 Qwen 3 Coder 7B)**
* **理由**：這是目前 10B 以下最強的寫程式模型。它在 Python、JavaScript、C++ 的表現甚至能與 GPT-4 縮短差距。
* **記憶體佔用**：約 4.7GB (Q4 採樣)，非常輕量，能留很多空間給 Context。
* **指令**：`ollama run qwen2.5-coder:7b`


* **第二名：DeepSeek-R1-Distill-Qwen-14B**
* **理由**：如果你需要 AI 幫你「debug」或「思考複雜邏輯」，這款透過 DeepSeek R1 蒸餾的模型非常強大，它會輸出思考過程。
* **記憶體佔用**：約 9GB，對於 16GB 的 Mac 來說剛好是邊緣，跑起來會比 7B 慢，但更聰明。
* **指令**：`ollama run deepseek-r1:14b`


* **第三名：Llama 3.1 8B / Llama 4 Scout**
* **理由**：最全能、生態系支援最廣。如果你除了寫程式還要它幫忙寫 e-mail 或文件，這款最平衡。
* **指令**：`ollama run llama3.1:8b`



---

### 2. `num_ctx` 要開多少？

這取決於你電腦的記憶體剩餘量。在 Mac 上，16GB 記憶體要同時分給系統、瀏覽器、IDE (VS Code) 和 AI。

* **建議設定值：`16384` (16K) 到 `32768` (32K)**
* **預設值 (2K/4K)**：太短了，AI 讀了幾十行代碼就會忘記前面的變數定義。
* **16K (推薦)**：大約可以讀入 **400-600 行代碼** 加上一些對話。這在 16GB RAM 上非常穩定，不太會造成系統卡頓。
* **32K (極限)**：如果你要處理一個完整的專案檔案，可以開到 32K，但此時你的 Mac 可能會因為 Swap 頻繁而變得反應遲鈍。



> **計算參考**：對於 7B 模型，每 1000 個 Token 的 Context 大約佔用 0.5MB - 1MB 的 VRAM。開到 16K 只會多佔用幾百 MB，重點在於模型本身的權重大小。

---

### 3. 如何在 Ollama 中設定？

你可以直接在 `ollama run` 之後動態設定，或永久修改模型：

#### 方法 A：執行時動態設定

```bash
ollama run qwen2.5-coder:7b
# 進入對話後輸入
>>> /set parameter num_ctx 16384

```

#### 方法 B：建立自定義 Modelfile (推薦)

如果你希望每次開啟都是這個大小，請建立一個檔案叫 `coding.mf`：

```dockerfile
FROM qwen2.5-coder:7b
PARAMETER num_ctx 16384
PARAMETER temperature 0.2  # Coding 建議調低，讓結果更精確

```

然後執行：`ollama create my-coder -f coding.mf`，之後只要 `ollama run my-coder` 即可。

---

### 4. Mac Mini M4 的特別建議

* **不要挑戰 32B 以上模型**：16GB RAM 跑 32B 模型會非常吃力，速度可能掉到每秒 1-2 個 Token，完全無法用於 Coding。
* **搭配 VS Code 套件**：建議安裝 **Continue** 或 **Cody** 插件，並將 Provider 設為本地的 Ollama，這樣你就可以直接在編輯器內進行 Code Completion，體驗最好。
